## Learned User Preferences

- Agency work surface / time tracking should match Clockify UI and UX closely (including action parity); avoid inventing custom flows that diverge from Clockify unless explicitly requested; waste (and similar) marks must apply only to the targeted entry, never auto-select or mark a whole day/group when marking one; Tracker waste is a dismissible tag (X to unmark); live Reports uses a dedicated Waste column before time (waste/mark states) with the same unmark UI as Tracker entry logs—including bulk unwaste on grouped rows—plus a quiet rectangular waste treatment (not wavy strike, not spanning project/actions); Tracker should include an industry-standard collapsible My Tasks right rail (prefer shadcn): both list-manage and play-to-track on existing project tasks (not a separate personal-todo model); filter pills not tabs; docked sibling on desktop with Sheet on small screens; rail styling and top edge align with the tracker (no offset); group by client with per-task `Assigned by X · Project name`; project/client pickers reuse the tracker task-chooser pattern; owners use multi-select with visible avatars; morphing transitions on task state enter/leave.
- Prefer choosing an existing task over creating a new one in task selectors and suggestions; do not use dedicated clear-X or switch/replace icon buttons on the tracker task chooser or time-entry rows—change tasks by opening the task chooser itself.
- Timer and time-entry state must persist on the server (DB or Redis), not browser or device storage, must survive refresh, and must stay editable mid-tracking with changes durably saved.
- Optimistic UI must not flicker or diverge from server/cache truth; for critical task/timer CRUD, prefer DB/cache-confirmed updates over local-only optimistic state; focused tracker/description inputs must not stutter or lose edits from live timer or cache sync while typing; timer start/stop must queue (no silent drops); pending/saving and stop blockers must be visible and accessible; picking a description suggestion must flush so mid-track description sync does not stick.
- Workspace agent (Orch) should be available above all pages and unified across Agency and Canvas (create/edit/plan for both, with seamless Agency↔Canvas transition); Agency supports Ask / Plan / Agent (writes never apply directly — propose or confirm-plan into pending proposals with before/after `ui_present` illustration, then human Approve/Reject); `ui_present` should preview and author all canvas block types; keep agency tool calls lean/token-efficient and prefer `ui_present` canvases when useful (avoid noisy tool spam with no artifact); artifact canvases must be openable from the creating message; the latest question, plan-approve, and canvas should stay sticky at the chat end (Cursor-like) with deliberate delight animation; composer history and sniper mode use a floating bill; scope/design selection uses app-suitable terminology and is not click-only; collapsed composer expands on hover and collapses on click-outside, with morphing expand/collapse animation (collapsed pill sits lower and wider); an active working thread shows a collapsed shimmer (hover: “Working…”); non-Agent modes and active scope appear as icon+removable dismissible tags that clear back to Agent; model picking uses Fast/Balanced/Pro tiers with Auto and Free toggles, shown as a single-word label with tooltip details (not a flat model list alone); composer toolbar controls have tooltips; attach merges into the plus menu; composer supports paste/upload attachments (images plus txt/md/json).
- When verifying agency UX, use the browser; for Clockify-parity work, compare against Clockify in-browser until the goal is met; for major UI redesigns, create multiple full user-journey approaches in Open Design first (real UX/UI/animation—not showcase-only), then confirm before implementing.
- Default git branch for rebase, merge, deploy, and fix PRs is `dev`; when explicitly asked for commits on multi-step work, prefer small micro-commits per logical update.
- Primary app navigation is a left sidebar rail shared by Canvas and Agency: team controls at the top (not a product logo; each team has one agency/team logo for profile), distinct sidebar background from the main content, a featured actionable Needs-action notification card in the rail footer (product Updates are always the highest-priority card—not buried in settings; dismiss/act advances to the next; overflow via a quiet “N more”; every notification actionable—not a passive bell-only inbox), and a Sign out button at the bottom (not a separate page); reference-style profile card whose avatar opens account actions/preferences (including notifications), and the sidebar collapse button in the top bar; no outer padding around sidebar/top bar, no expand-on-hover, and Agency section tabs should remain reachable via hover menu when the rail is collapsed; sidebar and top bar must read as one connected shell surface; the Agency top-bar segment crumb opens a segment switcher menu (not a static label only); Management secondary panes drill into the full primary rail (including the Canvas tab) as a nested list styled like the sidebar with a thread line for nested routes, with a recognizable Back control that works in compact/collapsed mode and only swaps rail content (stay on the current Management page; leave Management via the segment switcher); member avatars should match the shared AgencyMemberAvatar treatment used elsewhere.
- Styling should stay on the standard shadcn theme tokens (light and dark); prefer base theme tokens over custom ones; use shadcn primitives (e.g. Checkbox, Select, Collapsible, Label, Calendar + Popover date picker) instead of custom/native or Block* inputs—especially on Agency settings forms; leave/date-range calendars should stay open until explicit confirm; on member profile prefer “Off days” terminology over Leave, and contribution-day click should offer select-range or add-off-day using that same calendar pattern; Money dialogs should reuse the Dashboard command-bar client chooser (single-select) and the member-profile off-day time-range chooser; contribution heatmaps (member profile and Agency Resourcing team presence) keep fixed square size and fill empty days as zero/empty cells (do not shrink the grid); Resourcing presence is one team heatmap for who is working vs absent/out—not separate workload vs working tabs; do not add custom styling to shadcn UI components unless needed; when applying an external theme pack, keep the product fonts; do not use liquid glass (`ui-liquid-glass-*` / canvas ui-chrome-glass) for overlays or Canvas chrome—replace with standard shadcn surfaces; Tracker chrome should use default card borders (avoid colorful status borders); stop/blocker alerts sit under the tracker bar, not in the main row; tracker main row height should match time-entry rows; tracker description focus should stay subtle (no bold/heavy focus ring); global toasts appear bottom-right.
- Time-entry durations must stay second-precise (`hh:mm:ss`) end-to-end with no rounding to whole minutes on save; start/end clocks may still display Clockify-style without seconds.
- Tracker description suggestions must never implicitly change or remove the selected task; a suggestion applies only when the user explicitly picks it, and editing the description must not resurrect a previously cleared task; the suggestion dropdown must align exactly to the description input (same left edge and width).
- When backfilling time entries from Cursor (including Cloud), OpenCode, and Codex chat/work history (agency-time-gap-fill), use a from→to range (default today), check/report first then insert only when asked; new entries must not overlap each other or existing entries, and report before/added/new-total hours.
